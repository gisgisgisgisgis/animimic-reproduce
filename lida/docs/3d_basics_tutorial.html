1. 全貌：一隻會動的 3D 動物＝幾個陣列＋一個函數

在電腦裡，3D 動物不是「一個東西」，而是幾個陣列。下面用 n 表示頂點數、m 表示三角形數、J 表示骨頭數。

陣列形狀意思屬於
V_restn × 3 實數每個頂點在靜止姿勢的 (x, y, z)Mesh
Fm × 3 整數每個三角形由哪 3 個頂點組成（存編號）Mesh
UVn × 2 實數每個頂點在貼圖上的座標 (u, v)Texture
TH × W × 3一張圖片Texture
parentJ 整數每根骨頭的父骨頭，形成一棵樹Skeleton
Wn × J 實數每個頂點受每根骨頭影響多少Skin weights

動畫就是一個函數：給第 t 幀每根骨頭的姿勢 θt，算出這一幀所有頂點的新位置。

V(t) = Skinning( V_rest, W, FK(θt) ) FK＝正向運動學（第 6 節），Skinning＝把骨頭的運動傳到皮上（第 8 節）
最重要的一句話：動畫時只有頂點位置 V 在變；F、UV、T、W 全部不變。所以「讓模型動起來」在數學上就是找 θt ↦ V(t) 這個函數，而 AnimaMimic 的工作是反過來：看著影片去猜每一幀的 θt。

整條流程長這樣（第 10 節會再回來看）：

θt骨頭姿勢
→
FK每根骨頭的矩陣
→
LBS頂點位置 V(t)
→
可微渲染算出畫面
→
Loss和影片比

↺ 梯度沿著箭頭反方向傳回 θt，更新姿勢，重複幾千次。

2. Mesh：用分段平面去逼近一個曲面

定義。三角網格 M = (V, F) 是一個 piecewise-linear 曲面：真實的動物表面是光滑的，我們用很多小平面三角形去逼近它。這裡有兩種資訊要分清楚：

  • Geometry（幾何）＝ V：每個點在哪裡。
  • Topology／connectivity（拓樸）＝ F：誰和誰相連。邊（edge）不用另外存，從 F 就推得出來：每個三角形有 3 條邊，相鄰兩個三角形共用一條。

這種存法叫 indexed face set：頂點只存一次，三角形存的是編號。好處是改一個頂點的位置，所有用到它的三角形都跟著動，不會裂開。

拓樸的檢查：Euler characteristic（歐拉示性數）

V − E + F = 2 − 2g V、E、F 是頂點、邊、面的數量；g 是 genus（洞的數量，甜甜圈 g = 1，球 g = 0）

對封閉的三角網格，每個面有 3 條邊、每條邊被 2 個面共用，所以 3F = 2E。代進上式（g = 0）得到 F ≈ 2V、E ≈ 3V。

法向量（normal）

n = (b − a) × (c − a) ／ ‖(b − a) × (c − a)‖

三角形 (a, b, c) 的法向量由叉積算出；方向由頂點順序（winding order，通常逆時針）決定。渲染時用它判斷三角形朝向鏡頭還是背對鏡頭（back-face culling），也用它算光照：越正對光源越亮（Lambert：亮度 ∝ max(0, n·l)）。

實驗 1：一顆球的網格
拖曳旋轉。調細分層數，看 V、E、F 怎麼變，以及 V − E + F 為什麼永遠是 2。勾「變形」只改 V（幾何），F（拓樸）完全不變——這就是動畫在做的事。
在我們的專案裡　貓的 mesh 焊接後有 V = 30,002、E = 90,000、F = 60,000，所以 V − E + F = 30,002 − 90,000 + 60,000 = 2：一個封閉、沒有洞的曲面。這就是我說「Hunyuan3D 重建出來的幾何是 360° 完整的」的數學根據。

為什麼檔案裡的頂點比「真正的點」多？（焊接，welding）

glTF 這類格式規定一個頂點只能有一組屬性（一個 UV、一個法向量）。同一個空間位置，如果在兩個三角形裡需要不同的 UV（例如貼圖的接縫），就必須拆成兩個頂點。所以：

  • 貓的 rigged.glb 裡有 179,896 個頂點，幾乎每個三角形都有自己的 3 個頂點。
  • 做幾何計算（權重平滑、ARAP）前，要把「位置相同」的頂點合併回來，叫 welding，合併後剩 30,002 個。
  • 不焊接的後果：接縫兩邊被當成不相連，各自平滑、各自變形，皮就會在接縫處裂開。之前馬被撕裂，就是原因之一。

Mesh 從哪裡來

Hunyuan3D-2 不直接輸出三角形。它先預測一個隱式場（implicit field，例如 SDF：空間中每一點到表面的有號距離，裡面為負、外面為正），再用 Marching Cubes 演算法在「值＝0」的等值面上抽出三角形。gpu5 記錄裡的「Volume Decoding」就是在 3D 格點上逐格算這個場。其他 3D 表示法還有點雲、體素、NeRF、3D Gaussian Splatting；mesh 的優點是明確、渲染快、容易綁骨架，所以動畫業界都用它。

3. 重心座標：三角形內每一點的「地址」

三角形 (a, b, c) 內任何一點 p 都能唯一寫成三個頂點的加權平均：

p = α·a + β·b + γ·c，　α + β + γ = 1 p 在三角形內 ⇔ α, β, γ 都 ≥ 0。α 等於「p 和 b、c 圍成的三角形面積」除以整個三角形面積，β、γ 同理。

這是 mesh 上所有內插的基礎：頂點上存的任何東西（顏色、UV、法向量、甚至蒙皮權重）都用同一組 (α, β, γ) 內插到三角形內部。

實驗 2：拖動 P（或三個頂點）
三個頂點分別是紅、綠、藍；三角形內每個像素的顏色＝ α·紅 + β·綠 + γ·藍。把 P 拖出三角形，看哪個係數變成負的。
在我們的專案裡　把 gpu5 生成的多視角貼圖搬到我們的模型上（scripts/transfer_painted_texture.py）時，兩邊的三角形順序完全一樣，所以每個貼圖像素只要記住「在第 f 個三角形、重心座標 (α, β, γ)」，到另一邊用同一組數字就找到同一個點——精確對應，不必做最近點搜尋。

4. Texture 與 UV 參數化：把 2D 圖片包到 3D 曲面上

UV parameterization 是一個映射 φ：曲面 → [0, 1]²，給每個頂點一個 2D 座標 (u, v)。曲面上任一點的顏色是：

color(p) = T( α·uva + β·uvb + γ·uvc ) 先用重心座標內插出 UV，再到圖片 T 上取色（取色時通常用雙線性內插）。圖片上的像素叫 texel。

一個三角形在 UV 平面上的形狀，和它在 3D 裡的形狀不一定一樣。不一樣的話，貼圖就會被拉長或壓扁——這叫參數化扭曲（distortion）。

實驗 3：拖動左邊的 UV 三角形，或右邊畫面上的三角形
左：貼圖空間（u 向右、v 向上）。右：畫面上的三角形，用左邊框起來的那塊貼圖填滿。兩邊形狀差越多，「拉伸比」越大。

為什麼一定會有接縫（seam）

有彎曲的封閉曲面，不可能不切開、不變形就攤平到平面上（Gauss 的 Theorema Egregium：高斯曲率在不拉伸的映射下保持不變，而平面的曲率是 0）。地圖投影永遠有變形、橘子皮剝下來攤不平，都是同一個道理。所以 xatlas 這類工具會把曲面切成很多塊（charts），每塊各自攤平，再排進同一張圖（atlas）。切口就是接縫，接縫上的頂點需要兩組 UV——又回到上一節的焊接問題。

在我們的專案裡　第 0 幀只看得到動物的一側，所以 UV 一開始是「把第 0 幀直接投影上去」。之後 scripts/bake_texture.py 用 xatlas 給模型做一張 2048×2048 的 atlas，看不到的那一側先用鏡射補；再後來用 Hunyuan3D-Paint 生成六個視角，做成「混合」貼圖。

5. 渲染（rendering）與可微分渲染

渲染＝從 3D 場景算出 2D 畫面。光柵化（rasterization）分三步：

  1. 投影（projection）：針孔相機。點先轉到相機座標 Xc = R·X + T，再除以深度：
    x = f · Xc ／ Zc + cx，　y = f · Yc ／ Zc + cy f 由視角（fov）決定。除以 Zc 就是「越遠越小」。我們的 camera.json 存的就是 R、T、fov；「相機擬合」就是在估這幾個數。
  2. 覆蓋測試（coverage）：每個三角形蓋到哪些像素。同一個像素被好幾個三角形蓋到時，用 z-buffer 留下 Zc 最小（最靠近鏡頭）的那個。
  3. 著色（shading）：用重心座標內插 UV 取貼圖顏色，再乘上光照。

可微分渲染：AnimaMimic 能運作的關鍵

我們要用梯度下降調整姿勢，就需要「頂點往左移一點，畫面會變好還是變差」的梯度。問題是傳統光柵化的覆蓋是 0 或 1 的跳躍函數：頂點稍微動一下，要嘛完全沒有像素改變（梯度 0），要嘛某個像素突然翻轉（梯度不存在）。解法是讓覆蓋率變平滑：

coverage(pixel) = sigmoid( −d ／ σ ) = 1 ／ (1 + ed／σ) d＝像素中心到三角形邊界的有號距離（內部為負）。σ 越大邊緣越軟、梯度能傳得越遠；σ → 0 就退回硬邊緣。
實驗 4：硬邊緣 vs 軟邊緣，以及為什麼梯度會消失
「影片」是三角形在位移 0 的位置（虛線）。左右拖位移，右邊畫出 Loss＝Σ(覆蓋 − 影片)²。硬邊緣的曲線是一階一階的樓梯，斜率幾乎處處是 0；軟邊緣是平滑的碗，每一點都有斜率。按「走一步」用梯度下降試試看。
在我們的專案裡　animamimic/render.py 的 RasterRenderer 就是這樣：純 PyTorch 寫的軟光柵化器，可以在 CUDA 和 Mac 的 MPS 上跑。參數 --sigma 控制邊緣軟硬：優化時用 1e-5 ~ 1e-4（梯度範圍大），給你看的成品用 1e-6（幾乎是硬邊緣）。

6. Skeleton 與正向運動學（Forward Kinematics）

資料結構。骨架是一棵有根的樹，叫 kinematic tree：J 個關節，每個存它的父節點 parent[j]，根節點（通常是骨盆）的父節點是 −1。每個關節帶一個相對於父節點的剛體變換，屬於 SE(3)（三維旋轉＋平移），用 4×4 齊次矩陣表示：

Lj = [ Rj　tj ; 0　1 ]，　Rj ∈ SO(3)：RTR = I，det R = 1

正向運動學（FK）：把局部變換沿著樹一路乘下來，得到每根骨頭的全域變換：

Groot = Lroot，　Gj = Gparent(j) · Lj 依拓樸順序從根算到葉子。因為是連乘，轉動肩膀，整隻手臂（所有子孫）都會跟著轉。
實驗 5：三節手臂的 FK
調三個關節角度。虛線是靜止姿勢（rest pose）。橘色點「黏」在第 3 根骨頭上：它的位置＝ G₃ · (它在骨頭 3 自己座標系裡的位置)。下方是每根骨頭的全域矩陣 G（2D 用 3×3 齊次矩陣）。

Rest pose 與 inverse bind matrix

綁骨架時的靜止姿勢叫 bind pose，此時骨頭 j 的全域變換記為 Bj。真正拿去變形頂點的矩陣是：

Mj = Gj · Bj−1 先用 Bj−1 把點從世界座標轉進「骨頭 j 自己的座標系」，再用 Gj 轉回「擺好姿勢後的世界」。靜止時 Gj = Bj，所以 Mj = I，模型不動。glTF 檔裡的 inverseBindMatrices 存的就是 Bj−1。

為什麼要骨架：降維

直接調每個頂點：貓有 18 萬個頂點 × 3 ≈ 54 萬個未知數，每幀都要估，一定會亂扭。用骨架：23 個關節 × 3 個旋轉角，加上少量平移，約 70 個參數。骨架把可能的變形限制在一個低維子空間裡——這本身就是很強的先驗（prior），也是一種正則化。

7. Skin weights：一個有約束的矩陣

W ∈ ℝn×J，wij 表示頂點 i 受骨頭 j 影響多少。三個約束：

  • 非負：wij ≥ 0
  • 總和為 1：Σj wij = 1（partition of unity），讓結果是各骨頭結果的凸組合
  • 稀疏：每個頂點只記影響最大的幾根（glTF 慣例最多 4 根）

權重從哪來：

  • 美術師手畫（Hugging Face 上那頭牛就是）。
  • Bone heat（Baran & Popović 2007）：把骨頭當熱源，在 mesh 上解熱擴散方程。
  • Bounded biharmonic weights（Jacobson et al. 2011）：在約束下最小化權重的「彎曲能量」，得到很平滑的權重。
  • 神經網路預測：UniRig、RigNet。我們用 UniRig。

我們的權重平滑＝在 mesh 上做熱擴散

wi ← (1 − λ)·wi + λ · (鄰居權重的平均) 這是離散 Laplacian smoothing，等於熱方程 ∂w／∂t = Δw 的顯式時間步進。每做一步，權重的「突變」就被抹平一點。

為什麼要平滑？下一節會看到：權重變化越快的地方，皮被拉扯得越厲害。實驗 6 可以切換「顯示權重」看它長什麼樣子。

8. Skinning：Linear Blend Skinning（LBS）與表面拉扯

vi′ = Σj wij · Mj · vi　＝　( Σj wij Mj ) · vi 每根骨頭各自把頂點搬到一個位置，最後按權重加權平均。

優點：對頂點、對權重都是線性的；GPU 一次算完；處處可微——所以 Stage 1 才能把「姿勢 → FK → LBS → 渲染 → loss」整條鏈用 autograd 反向傳播。

缺陷：為什麼皮會被拉扯

把 LBS 看成從靜止曲面到變形後曲面的映射 x ↦ x′。表面會不會被拉長，由它的 Jacobian（局部線性近似）決定：

∂x′／∂x　=　Σj wj Aj　＋　Σj (Mj x) ⊗ ∇wj Aj 是 Mj 的旋轉部分；⊗ 是外積；∇wj 是權重沿表面的梯度。
  1. 第一項：旋轉的平均不是旋轉。兩根骨頭相對轉了 θ、權重各一半的地方，平均矩陣是
    ½ (I + R(θ)) = cos(θ／2) · R(θ／2)
    也就是「轉一半，再縮成 cos(θ/2) 倍」。θ = 90° 縮成 0.71 倍；θ = 180° 縮成 0——皮被扭成一條線，這就是有名的 candy-wrapper artifact（糖果紙效應）。
  2. 第二項：權重變化快的地方被撕開。因為 Σj ∇wj = 0，這一項其實是「權重變化有多快」乘上「兩根骨頭對同一點的預測差多遠」：
    拉伸 ≈ ‖∇w‖ × ‖Mj x − Mk x‖
    權重越陡（過渡帶越窄），兩根骨頭一分開，中間那條窄帶就被硬拉長。

所以有個兩難：過渡帶太窄 → 第二項大（窄帶被撕開）；過渡帶太寬 → 第一項影響的範圍變大（一大片都縮水）。在下面的實驗把兩邊都試試。

實驗 6：彎曲一根管子——LBS 的拉扯，與 ARAP 的修正
左半黏在骨頭 1、右半黏在骨頭 2，中間的過渡帶寬度可調。顏色＝拉伸熱圖（白＝沒拉伸，紅＝拉長或壓縮 30% 以上）。先把過渡寬度調到最小，看外側被撕開；再調到最大，看內側整片縮水；最後打開 ARAP，拉 λ 看「越剛」和「越貼近原動作」之間的取捨。

9. ARAP：盡可能剛性（As-Rigid-As-Possible）

ARAP（Sorkine & Alexa 2007）的想法：允許每一小塊表面旋轉（所以可以彎曲），但不允許它被拉長或歪斜。每一幀解這個最佳化問題：

minx, R　Σi Σj∈N(i) wij ‖ (xi − xj) − Ri (pi − pj) ‖²　＋　λ Σi ‖ xi − yi ‖² p＝靜止位置，x＝要解的新位置，y＝LBS 算出來的位置，Ri＝頂點 i 那一圈鄰居的最佳旋轉，N(i)＝鄰居，wij＝邊的 cotangent 權重（和蒙皮權重 W 是不同的東西）。第一項要求每一圈鄰居只是被轉了一下；第二項要求不要離原本的動作太遠。λ 越小越「剛」，但離 LBS 越遠。

用交替最佳化求解：

  1. Local step：固定 x，對每個頂點找最佳旋轉 Ri。這是 Procrustes 問題：把 Si = Σ wij(pi−pj)(xi−xj)T 做 SVD，Ri = V UT，有封閉解（和 Kabsch 演算法一樣）。
  2. Global step：固定所有 R，目標對 x 是二次式，解一個稀疏線性系統 (L + λ·A) x = b。矩陣 L 是 cotangent Laplacian，和 x 無關，所以只分解一次，之後每次迭代都重用。

實驗 6 打開「套用 ARAP」就是這個演算法（2D 版本，用 Gauss–Seidel 迭代解線性系統）。注意實驗裡的管子很粗、又只在一個關節處大角度彎曲：在這麼短的距離內彎折一個厚的物體，內側一定要被壓縮一些（物理上也是），所以 ARAP 只能把它從「集中在一條窄帶」變成「平均分攤」，λ 越小分攤得越開、但離原動作越遠。真實動物的彎曲平緩得多，所以在貓、狗、狼上效果比實驗裡好。

在我們的專案裡　scripts/arap_refine.py，λ = 0.01。結果（最糟 1% 的邊被拉長多少，全段平均）：

和影片的輪廓貼合度幾乎不變（貓的 IoU 0.8904 → 0.8905）。另外我們也驗證過：把骨頭的小位移歸零，拉扯沒有變少——拉扯真的來自 LBS 本身。

10. 串起來：Stage 1 就是一個逆向渲染問題

正向渲染：給 3D 場景 → 算畫面。逆向渲染（inverse rendering）：給畫面 → 猜 3D 場景。AnimaMimic 的 Stage 1：

未知數：θt = { r6d, t }，每幀約 70 個數
正向模型：θt →(FK)→ Mj →(LBS)→ V(t) →(可微渲染)→ 輪廓、顏色、深度
目標：minθ Σt [ 輪廓 loss ＋ 顏色 loss ＋ 追蹤點 loss ＋ 深度 loss ] ＋ 正則項
求解：Adam，3000 次迭代，梯度由 autograd 一路傳回 θ

這個思路叫 analysis-by-synthesis：先猜一組參數 → 畫出來 → 跟觀察比 → 沿梯度修正 → 重複。四種 loss 的資料來源：輪廓來自 SAM2 切出的遮罩，追蹤點來自 AllTracker，深度來自 VGGT，顏色就是影片本身。

灰色是「影片」裡的手臂（姿勢藏起來了），藍色是我們的模型。Loss＝對應點距離的平方平均（像 Stage 1 的追蹤點 loss）。按「開始」用梯度下降去猜姿勢。學習率太大會怎樣？
